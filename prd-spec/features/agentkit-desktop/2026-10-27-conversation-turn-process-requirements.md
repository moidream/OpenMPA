# React Desktop 对话执行过程：用户与需求

## 4. 用户、调用方与场景

| 场景            | 角色     | Given                                     | When                          | Then                                                         |
| --------------- | -------- | ----------------------------------------- | ----------------------------- | ------------------------------------------------------------ |
| 查看运行中 Turn | 桌面用户 | 会话已接受请求并开始产生 SSE              | 用户停留在对话底部            | 执行过程展开，已完成步骤显示摘要，当前步骤显示运行状态       |
| 阅读完成答案    | 桌面用户 | Turn 已终止且有最终答案                   | 终止事件到达                  | 执行过程折叠为步骤数与耗时摘要，最终答案保持展开             |
| 查看工具详情    | 桌面用户 | 某工具步骤有可展示详情                    | 用户展开该工具行              | 只显示经过 Go 侧安全处理的输入和输出预览                     |
| 跳到完整 Trace  | 桌面用户 | 工具步骤有 invocation，且可能有 step 关联 | 用户选择“在完整 Trace 中查看” | Trace 打开当前 invocation。有稳定 step 关联时同时选中该 step |
| Trace 不可用    | 桌面用户 | 普通 Session Trace 返回 404               | 用户查看对话或打开 Trace      | 对话内执行过程继续可用，Trace 显示现有 admin_debug 限制      |
| 重连与回放      | 桌面用户 | SSE 中断后按 cursor 恢复，或重新读取历史  | 相同事件再次进入投影          | 既有 segment 原位更新，不生成重复内容                        |
| 隐藏 reasoning  | 桌面用户 | 事件没有显式可展示授权                    | reasoning 事件到达            | UI 可以显示通用运行状态，但不显示 reasoning 文本             |
| 长 Markdown     | 桌面用户 | 助手流式生成长代码块或宽表格              | 用户向上阅读                  | 内容继续更新，但滚动位置不被拉回底部，布局不横向撑破         |

## 5. 需求与约束

### 5.1 功能需求

| ID   | 来源                         | 优先级 | 触发/适用范围                     | 必须行为或约束                                                                                    | 可观察结果/度量                                              |
| ---- | ---------------------------- | ------ | --------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| FR-1 | 用户原始请求、FACT-11        | 必须   | 每个有 invocation 的 Turn         | 在最终答案旁显示可折叠执行过程，并按真实事件顺序保留 reasoning、工具和状态 segment。              | 运行中 Turn 可见当前步骤，完成 Turn 显示折叠摘要。           |
| FR-2 | 用户原始请求、FACT-11        | 必须   | Turn 状态变化                     | 运行中保持过程展开。完成、失败或停止后折叠，并显示相应结果摘要。                                  | 同一 Turn 的 disclosure 状态符合状态表。                     |
| FR-3 | 用户原始请求、FACT-11        | 必须   | reasoning 事件                    | 只有显式授权的 reasoning 文本可以显示。流式阶段显示已完成段落摘要，完成后显示首行摘要并允许展开。 | 隐藏 reasoning 不出现在 DOM；可展示 reasoning 有摘要和详情。 |
| FR-4 | 用户原始请求、FACT-1、FACT-2 | 必须   | tool call 与 result               | 通过 `toolId` 关联同一工具的准备、运行、成功、失败和停止状态，并使用安全摘要。                    | 调用与结果只占一行并原位更新。                               |
| FR-5 | 用户原始请求、FACT-4、FACT-5 | 必须   | 助手文本                          | 保留 GFM，并补齐代码块工具栏、复制、换行、宽表格、长路径和窄屏行为。                              | 既有 GFM 表格测试继续通过，新边界用例有唯一结果。            |
| FR-6 | 用户原始请求、FACT-6         | 必须   | 用户从工具行查看诊断              | 打开精确 invocation。存在已验证关联时选中对应 Trace step，否则停在 invocation 级别。              | 不按名称或时间猜测 step。                                    |
| FR-7 | 用户原始请求、FACT-6         | 必须   | Trace 返回 404、401、403 或空数据 | 保留现有 Trace 错误语义，对话内执行过程继续工作。                                                 | Trace 失败不删除或替换对话 segment。                         |
| FR-8 | FACT-3、FACT-9               | 必须   | schema v1 历史或旧 Runtime        | v1 文本与工具摘要继续渲染。v2 才启用结构化详情。                                                  | 混合版本不会白屏或丢失最终答案。                             |

### 5.2 非功能约束

| ID    | 来源                  | 优先级 | 触发/适用范围                | 必须行为或约束                                                                                                         | 可观察结果/度量                                                           |
| ----- | --------------------- | ------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| NFR-1 | FACT-7                | 必须   | reasoning、工具和 Trace 详情 | 敏感内容在 Go 到 WebView 边界前过滤。React 再执行防御性过滤。通用工具不得默认展示原始 payload。                        | 安全负控中的 token、Authorization、cookie 和 password 不进入 DOM。        |
| NFR-2 | FACT-3                | 必须   | 流式、重连和历史回放         | 投影对同一事件幂等，按 invocation 与 segment 身份保持顺序，terminal 后收口未完成工具。                                 | 重放相同 fixture 后 segment 数量和顺序不变。                              |
| NFR-3 | 用户原始请求          | 必须   | 全部交互                     | disclosure 使用原生按钮语义和 `aria-expanded`。状态变化可读。计时 tick 不进入 live region。支持键盘与 reduced motion。 | 自动化可访问性断言和键盘用例通过。                                        |
| NFR-4 | 用户原始请求、FACT-11 | 必须   | 长回复与长记录               | 使用同一 fixture 记录变更前后数据。没有测量证据时不宣称性能提升，也不引入增量解析或虚拟列表。                          | 基线与复测报告包含场景、输入、命令和结果。                                |
| NFR-5 | FACT-4、FACT-10       | 必须   | Phase 0 到 Phase 3           | 优先复用 React、`react-markdown` 和现有依赖。新增运行时依赖需要独立决策和构建影响证据。                                | `package.json` 在没有新决策时不增加运行时依赖。                           |
| NFR-6 | FACT-8                | 必须   | 最终验收                     | 测试和普通 Vite 页面不能代替真实 MyGo 应用验收。                                                                       | 验收记录包含真实会话的运行中、完成、失败、长 Markdown 和 Trace 联动证据。 |
