## 设计与所有权

Go `usage.Service` 保留 Runtime 契约解析及验证。独立 IPC 边界将单个请求对象与
`{ok,value,error}` 结果连接到 MyGo，隐藏 context 和内部快照。
React 通过 `DesktopServices` 的类型化资源入口调用，页面不自行发 HTTP 请求。
原生 rail 只负责导航，React 负责资源和协作内容。
会话草稿由 AppState 按连接 epoch、scope 和 sessionId 持有，Chat 的异步回执只能修改对应草稿。
资源页面的版本快照和可编辑正文分离；失败或重新读取保留正文，显式放弃才能替换。

对比一个 Usage 绑定与两个 Resources/Collaboration 绑定后，选择一个 Go Usage 绑定，
在 React 服务层提供两个可注入的资源/协作接口。两种方案都复用同一 Runtime 传输；
单绑定减少包装维护，同时保留独立页面测试。Main Profile 使用 Go 持有的一次性快照标识，
不允许从浏览器返回的 JSON 重建权威配置。委派调查与独立设计审查已完成。

阶段：契约调查 → 两种设计比较 → 代码实施 → 边界验证 → 两轮审查 → 全量验证。
委派可用，模型继承主会话；本环境不提供不同模型比较。
