# 扫码等待时保持渠道页面可操作

## 问题与行为

原界面将 waiting / pending / registering / unknown 绑定状态用于禁用整个渠道页面，连取消、渠道标签和账号选择也不能点击。

改为仅在实际请求期间暂时禁用相关控件。等待扫码时可取消界面、切换渠道及选择已有机器人，继续查看状态和管理权限。取消只收起当前表单，不代表取消服务端操作；界面明确说明这一点。通过“恢复绑定”返回原二维码及原操作，不重新创建请求。

绑定结果、操作 ID 和恢复表单按连接 epoch、渠道及域隔离，飞书与 Lark 各自保留。切换渠道时暂停当前绑定轮询，返回后继续原操作；迟到的旧渠道响应不覆盖当前页面。绑定结果未知时仍禁止为同一渠道再次创建绑定。退出扫码或切换已有机器人后，后台完成绑定不会抢走当前账号选择。

## 验证

- 新增三项回归：等待扫码时取消及账号操作、飞书/Lark 操作隔离与未知结果保护、渠道切换后的迟到轮询。
- 前端全部 553 项测试通过；TypeScript、ESLint、格式、设计约束及桌面前端构建通过。
- 使用真实 React 组件与本地模拟 IPC，验证二维码出现后的取消、账号选择、切换 Lark、返回飞书恢复原二维码。无真实绑定写入或扫码授权。
- 当前原生客户端未选择 Runtime，本次不包含真实云端扫码完成的验证。
