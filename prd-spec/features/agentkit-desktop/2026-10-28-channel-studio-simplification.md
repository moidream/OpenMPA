# 渠道页按 Studio 收敛

日期：2026-10-28

## 背景与目标

用户指出渠道页面过于复杂，要求参考 Studio。此前把机器人列表卡片、所有绑定表单、账号权限及多种管理操作同时展示，常用路径不清晰。本次只调整渠道前端与对应文案，保留现有 Runtime 接口和多 Bot 身份约束；不改 A2A 行为，不修改云端机器人。

用户截图中的 A2A“协作任务”是会话草稿快捷入口：生成 @成员别名 + 任务内容，用户在所选会话确认发送后才执行。未选择会话时禁用入口，本次已解释其用途。

## 设计与实现

沿用既有语义主题、系统字体和控件尺寸，以当前机器人作为唯一管理对象：

```text
消息渠道                            刷新
飞书 | Lark | 钉钉 | 企业微信
机器人 [选择已绑定的 Bot]  新增  停用
已绑定 · 机器人名称 / ID             解除绑定
消息网关        入站路由        回复投递
群聊权限                              刷新
已授权群 / 添加群
> 高级设置
```

- 渠道标签始终独立于绑定表单，支持方向键切换。飞书和 Lark 仍以 domain 区分，并使用明确 provider+appId 操作。
- 多 Bot 时由用户选择，单 Bot 自动选中。默认仅显示选中机器人的绑定状态、三项健康信息和群权限，不再平铺每个机器人的操作卡片。
- 点击“新增机器人”后才渲染扫码/凭据绑定表单。移除重复的域名选择，domain 来自渠道标签。凭据仅保留在该表单状态，成功或取消后清除。
- 绑定操作 ID、恢复绑定、私聊授权、配置升级、机器人配置和模板收进高级区域；配置与凭据编辑使用现有 ModalDialog。
- 健康状态、群权限自动读取；未观测到回复不等于已经投递。每个 Bot 的群权限状态独立保存，晚到响应无法覆盖新选中的 Bot。
- 保留二维码轮询、未知结果禁止重复创建、原操作恢复、精确 Bot ID、私聊绑定槽位版本与配置版本校验。
- 只有显式用户操作才调用修改接口，页面展开、选择与状态刷新不会创建/删除机器人或修改权限。

- pass：549 个前端测试，覆盖原有绑定轮询、结果未知、私聊版本冲突、语言切换，以及默认不显示绑定表单、读取当前 Bot 的健康/权限和晚到响应隔离。
- pass：TypeScript、ESLint、Prettier、设计令牌检查、桌面前端构建、git diff --check。
- pass：Go 本地化包与 locales 检查；本次未修改 Go 的渠道请求逻辑。
- pass：实际 React 组件的模拟预览，检查机器人选择、按需展开新增、键盘切换渠道、375px 窄窗口及深色主题；窄窗口文档宽 360px，viewport 375px，无横向溢出。
