# M07 打包、发布与多平台准出 spec

状态：已接受，实施中。日期：2026-10-25。类型：功能。风险：L3，软件分发与本地数据升级。首次设计，无 issue/MR。需求来源：[PRD](../2026-10-25-prd.md) FR-11、NFR-1/NFR-2/NFR-5。事实：证据（私有研究，不随版本发布） FACT-3/FACT-13/FACT-14。前置已选模块验收完成与OPEN-1/OPEN-4/OPEN-5。

## 1. 结果与发布对象

产出可安装的MyGo桌面客户端，应用内含Go executable与静态前端，不带Node/Bun/Python服务。终端用户只需目标系统及对应WebView运行依赖。macOS/Windows/Linux分别记录构建、启动、编辑、对话框、秘密存储和更新证据；未验证平台不声称支持。

首批建议macOS arm64开发包，再正式.app/.dmg；universal和Windows/Linux在各自环境验证。名称/identifier/图标/签名主体/更新地址由OPEN-4决定，不使用虚构生产发布配置。

## 2. 构建与供应链基线

固定MyGo Go模块和runtime/CLI的匹配版本；当前checkout为0.6.4，消费源码时记录revision。开发local replace不进入可分发配置。Go/toolchain与Node frontend构建版本满足各仓库要求，锁文件/生成client与生产构建来自同一源版本。

CGO_ENABLED=0构建，生产禁用调试与任意IPC。当前Web脚本同时编译server，desktop包改用frontend-only构建；包检查无非必要后端及credential/.env。保留当前MIT和第三方notice。

新增M08平台接入发布检查：不捆绑Python AgentKit SDK/CLI/Studio进程，不内置云AK/SK、STS、RuntimeKey、OAuth client secret或用户登录缓存；Go签名依赖固定版本。SSO发现/public client公开配置与秘密分开，允许回调及发行identifier在目标环境真实验证。云登录和运行入站两层必须通过对应AC-16–AC-19才能宣称平台集成可用。首版用户要求的多Bot/渠道核心还需M09与E5通过AC-20–AC-24；P2a增量不能作为完整SessionBot首版发布。

MyGo官方CLI支持平台构建、.app/.dmg、Windows installer、Linux archive/deb；使用其真实Config字段。可先用本地CLI进行未签名测试包验证，不把未签名开发包当正式分发。需要签名/公证的操作在所有文件和结果具体可审阅后，按用户分发授权执行。

## 3. 数据、升级与恢复

application identifier稳定，.dev独立。首次安装不会复制另一应用的secret；若要迁入明确用户选择的配置，重新认证。更新保留PathUserData，schema检查和备份在打开写服务前完成。

新schema必须说明旧包可读性；升级先副本演练，失败不改有效store。回滚包遇未来schema以只读恢复/导出处理，不覆盖新稿。恢复旧备份需清楚说明会丢失哪些后续变更并获得具体确认，不能声称所有schema升级都无损可逆。

自动更新仅在用户确认的feed、公钥和production签名配置存在时启用，验证大小/hash/签名后安装。首版在调用Install前提供确认/取消；Install启动后进入不可撤销安装阶段，不提供保证保留旧包的取消按钮。MyGo下载后解包/交换没有全程context取消保证（M updater.go:221），错误或中断需按最终包状态/重启结果判断是否安装或恢复，不能仅据context取消显示已撤销。私钥不放仓库/renderer/诊断包。

## 5. 准出、观察与回退

发布清单包括source revision、依赖锁、生成绑定校验、Web/Go相关检查、GUI场景结果、包摘要、签名结果、协议能力表和已知限制。默认CI检查当前Web格式/lint/typecheck/tests/build；desktop补Go及生成检查，GUI由对应平台环境执行。

跨仓库隔离源码保存在忽略的`.openmpa/`时，各仓库必须使用自己的测试入口。主仓库Vitest保留默认发现范围与默认exclude，只额外排除`.openmpa/**`，避免执行Python SDK携带的Node测试或后端skill的Bun测试。`vitest.config.ts`不改变业务构建、生产包或既有主仓库测试匹配；标准`npm test`必须通过且报告实际主仓库数量，不能把外部仓库测试误计为产品回归。
