# 飞书绑定、多 Bot 与 A2A 界面修复

日期：2026-10-28

## 证据与范围

用户反馈飞书没有二维码、之前绑定的机器人不可见，要求保留 Studio 的多 Bot 行为，并整理 A2A 界面。只修改 OpenMPA；Studio 与 Runtime 仓库仅用于读取实现和测试契约。

Runtime 的飞书注册测试明确允许 verification_uri_complete 为 open.feishu.cn/page/launcher，而客户端原先仅接受 accounts.* 链接。旧列表投影也会因一个其他渠道缺少顶层 appId 而整体失败，并把缺少 channels 字段的响应当成空成功。这些兼容问题已通过先失败的回归测试复现。首次列表不一致的唯一历史原因未能从现有证据确认，不能断言机器人被删除或确实命中某一兼容问题。

实机读取 Studio 同一 Runtime，确认存在已启用机器人 mpa1013，且 Studio 显示曾成功投递回复。后端重载后用户在客户端内重新解锁凭据；重新读取同一 Runtime 后，客户端已显示相同机器人。发起一次真实的飞书扫码绑定，确认出现二维码并停留在等待扫码；未扫码授权、未新增机器人，未修改已有机器人。授权链接、二维码、凭据不写入测试素材或本文。

## 实现

- 飞书与 Lark 接受明确列出的官方 open.feishu.cn、open.larksuite.com launcher 主机，在 Go 内生成 PNG。继续禁止将第三方二维码 URL 或完整授权链接转发到页面；有效的内联 PNG/JPEG 不因缺少兼容链接被清空。
- 列表要求显式的 channels 数组。识别受支持渠道，兼容旧 config 中的 App ID / Client ID / Bot ID；缺少 ID 的历史其他渠道记录可见，但前端禁止对它发起账号操作。所有输出继续白名单投影，保留每个 Bot 的 provider+appId、domain 和 bindingType。
- 将已绑定机器人目录放在新增入口前。读取中、失败、空列表分别显示；请求序号防止旧响应覆盖新目录。飞书和 Lark 的账号选择分开，操作总是携带具体 Bot ID；只有一个机器人时自动选中，绑定完成后优先选择新返回的 ID。
- A2A 使用顶部空间连接区、左侧可搜索成员列表、右侧成员详情/别名/任务编辑区。创建空间、注册智能体和完整成员详情使用已有 ModalDialog，保留键盘关闭与焦点管理。分页仅多页显示，保留连接版本校验、别名版本校验、成员草稿隔离和晚到响应丢弃。协作任务仍只添加到会话草稿，不自动发送。

## 界面方向

复用现有主题和系统字体，正文、标题、辅助文本保持既有字号层级。以绑定目标和选中成员作为视觉锚点，减少重复标题和表单堆叠。采用项目已有浅色/深色 surface、foreground、border、focus、primary 语义令牌，不引入独立品牌色。窄窗口采用单栏并限制成员列表高度，长 ID 可换行。

## 验证与边界

- pass：547 个前端测试（101 个文件）。新增覆盖多 Bot / domain 映射、具体 Bot ID 权限请求、飞书与 Lark 过滤，以及读取失败不显示“无账号”。已有协作版本校验、草稿隔离与晚到响应测试保留。
- pass：Go 全量 go test -race ./... 与 go vet ./...；新增 launcher 二维码、旧其他渠道记录兼容和缺失目录非空成功测试。
- pass：TypeScript、ESLint、格式、设计令牌检查、桌面前端生产构建。
- pass：实际 React 组件的本地模拟界面验证双栏、注册表单 Runtime→端点联动、Escape 关闭、375px 窄窗口与深色主题。375px 时 DOM 文档宽 360px，无横向溢出。预览图仅包含模拟数据。
- pass：实机读到已有机器人，并生成真实飞书二维码。
- not_run：真实扫码后的新增/删除/停用/改配置，以及真实 A2A 绑定、注册和任务发送；验证未改动原有云端资源。

原先绑定不可见的历史触发条件未保留请求证据；当前读取已与 Studio 对齐。多 Bot 管理的列表、域名分离与确切 ID 操作通过模拟测试，真实环境只验证了已有单 Bot 读取。
